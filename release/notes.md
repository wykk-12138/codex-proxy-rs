# v3.29.7

## 升级说明

- 插件 RPC 协议由 v4 升至 v5，`upstream_adapter` 能力由 v3 升至 v4。现有插件需使用新 SDK 重新编译、打包后再配合本版宿主使用，仅修改清单版本不够；使用受影响接口的插件还需适配字节头、响应元数据和 WebSocket 原文类型，上游适配器将 `service_tier` 迁移到 `observation`
- 插件模型调用和受管 HTTP 出站统一采用现有 `responsesMaxDecompressedBodyBytes` 设置，默认 64 MiB。实际出站正文超限时返回 413 且不发送请求；调小此设置可能影响插件上传或转发，响应缓冲、流控窗口和模型 Token 上限不随之扩大

## 修复与调整

- 修复模型 request / attempt 插件中间件的长流在初始处理预算耗尽后被截断的问题；首个流式响应头交付后，正文沿用请求期限和取消机制，不再被默认 120 秒插件处理预算截断
- 修复插件大正文请求被模型回调、上游适配器编码或受管 HTTP 的固定上限提前拒绝的问题；正文预算随模型执行冻结，配置更新后新请求使用新值，无需重新启用插件
- 补全插件模型调用的客户端 IP、User-Agent 和上游响应观测；保留 HTTP 版本、重复头、非 UTF-8 头值、尾部头及 WebSocket 原文，失败和重试记录也保留对应观测。适配器未报告首输出计时时，按宿主请求起点记录首个非空输出；无来源的上游计时仍保持未知
- 修复备份等后台常驻任务在依赖恢复后仍保留连续失败和当前错误、导致健康检查持续返回 503 的问题；实际工作或依赖检查成功后恢复健康并重置重启退避，空闲和长任务不再按重启退避时长误判
- 账号编辑默认选中已绑定的出站代理并显示名称，直连账号显示直连；未更改选择时保留原绑定，批量编辑继续提供“保持当前”
- 修复 Windows Codex 版本检查扫描整个 MSIX 包、耗尽 HTTP Range 下载预算的问题
- 更新 `follow-redirects`、`rustls-webpki` 和 `webpki-roots` 依赖，修复已知依赖安全问题
