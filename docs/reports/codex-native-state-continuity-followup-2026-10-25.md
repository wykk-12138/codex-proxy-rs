# 原生状态连续性：外部审查后续修复

## 范围

独立审查针对 `54fd955e68d818b1ddfdf48279391b2252411f8a` 的原生状态连续性实现提出问题。本报告记录其中的处置结果与对应代码范围

- 原问题成立、修复方向合理
- 接受并修复：窗口 ID 合同、notes 写入取消与发送前失败、并发过期迁移
- 不接受：未知写重放与“后续完整响应可覆盖未知 append”、未证实的上下文字条目 ID 推断
- 保留为可选：全会话加载、互斥表增长与图片预算

## 已修复

### 窗口标识

`list_items`、`search_contents` 与 `read_item` 的窗口参数先按内部 ID 匹配，再按该 agent 已保存的
官方 `context_window_id` 解析。别名来自 history 条目、现存 response anchor 与 pending 输入三处成对元数据，
按 Key、会话与内部窗口关联；目录、顺序与条目数仍只由条目定义，空 anchor 或 pending 不创建窗口

未知的显式窗口返回空页或未找到，不再作为参数错误，也不退回全部窗口；同一 agent 下别名跨内部窗口歧义、
同一窗口声明冲突 agent 时保护性失败；存储错误与真实参数错误不被吞掉。持久内部 ID 的校验未放宽

### notes 写入生命周期

托管写把发送与落库交给受 Host 监督的交付任务，交接是唯一所有权转移点：

- 交接前取消不产生写意图，发送前可确定的准备失败不占用 seq
- 交接后调用方取消或丢弃响应不中断真实发送与结果观察；会话互斥、容量与账号租约随工作持有
- 在途写上限 32 个，无额外等待队列；容量在等待会话互斥之前占用，同一会话的等待者同样计入
- 上游从发送到完整正文 35 秒总时限，每次持久等待 30 秒硬上限，不延长 Host 关闭预算
- 交付接管前的准备有 60 秒强制窗口，只作用于被接管的写；notes 读与 legacy 写沿用调用方期限与已有选号预算
- `start` 失败先读回：只有可证明仍是 `unsent` 才记 `failed`，`in_flight`、`unknown` 与终态保持原状
- 完成记录提交不明时只报告持久失败，不覆盖可能已提交的 `responded`
- 首绑租约在取得账号时申请，期限覆盖真实强制的准备窗口与交接后的净交付预算，交接前复验剩余量
- 取得账号前已判定 legacy 时沿用调用方租约生命周期；取得交付租约之后才判定为 legacy 时，在写意图与发送前保护性失败

未装配 notes 持久端口时，Provider 贡献该任务类别的明确禁用项，保留 Host 完整任务计划校验；装配时注册真实 daemon

### 过期迁移

选号观测到的 owner 与代次随迁移意图携带，在会话锁内、保存任何重放事实之前复验。并发请求已发布新状态时，
旧意图不重放也不发送模型请求；目标恰好等于当前 owner 也不复用旧结论

## 未接受及原因

- **未知 write 直接重放**：整文件替换幂等不等于原请求已经执行，重放会引入原账号可能未发生的业务写入，属恢复策略变更
- **后续 `responded` write 消除先前的未知 append**：完整响应只表示传输完成，不是加密业务成功，不能证明覆盖成立
- **上下文条目 ID 不兼容的推断**：官方源码存在为缺失 ID 的条目分配声明 ID 的路径，真实短标记与声明 ID 的对应关系缺少证据，不据此改协议
- **全量查询与内存优化**：属可选改进，与本次正确性修复分开评估

未知或未终结写入仍阻止自动迁移，本轮不新增自动修复入口、恢复扫描或补偿队列
